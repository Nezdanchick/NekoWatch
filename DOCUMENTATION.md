## 1. Что это за приложение

NekoWatch — мобильное приложение для поиска и просмотра аниме. Оно не хранит
видео у себя: метаданные берёт с сайта Shikimori, а само видео открывает
в плеерах Kodik и Collaps через встроенный браузер.

**Четыре основные вкладки:**

| Вкладка | Что показывает |
|---|---|
| Главная | Четыре подборки: популярное, последние релизы, онгоинги, анонсы |
| Поиск | Поиск по названию с подгрузкой по мере прокрутки |
| Закладки | Ваши тайтлы, разложенные по статусам просмотра |
| Профиль | Время просмотра, история, выбор темы, ссылки на авторов |

**Дополнительные экраны:** карточка аниме, полноэкранный плеер,
история просмотров, полный список подборки.

**Что приложение умеет помимо очевидного:**

- запоминает закладки и историю между запусками;
- кэширует главную и карточки аниме, чтобы не дёргать сеть лишний раз;
- считает суммарное время, проведённое в плеере;
- три темы, включая Material You (палитра из обоев системы).

## 2. Откуда проект взялся

Это переписанная на Flutter версия существующего приложения на
**React Native (Expo)**. Оригинал лежит на уровень выше — в папках
`../app/`, `../components/`, `../services/`, `../store/`, `../types/`.

Почему это важно знать:

1. **Оригинал трогать нельзя.** Он остаётся рабочим приложением и служит
   образцом. Все изменения — только внутри `nekowatch_flutter/`.
2. **Слой данных перенесён один в один.** Адреса, тела GraphQL-запросов,
   заголовки, паузы между повторами, размеры страниц и лимиты кэша
   скопированы буквально. Если вы видите странное число вроде «10 попыток
   по 2 секунды» — это не случайность, так было в оригинале.
3. **Переписан только внешний вид.** Интерфейс собран заново на Material
   Design 3, но тексты кнопок и сообщений перенесены дословно.

В комментариях к файлам вы встретите строки вида
`// Порт components/AnimeCard.tsx` — это указание на файл-первоисточник.
Если сомневаетесь, как что-то должно работать, откройте его.

## 3. Установка и запуск

### Что нужно поставить

- **Flutter SDK** 3.24 или новее — https://docs.flutter.dev/get-started/install
- **Android Studio** (ради Android SDK и эмулятора)
- переменную окружения `ANDROID_SDK_ROOT` или `ANDROID_HOME`

Проверить готовность окружения: `flutter doctor`.

### Первый запуск

```bash
cd nekowatch_flutter
flutter pub get       # скачать зависимости
flutter run           # запустить на устройстве или эмуляторе
```

Если в проекте нет папки `android/` (например, вы клонировали только `lib/`),
сначала сгенерируйте нативную обвязку:

```bash
flutter create --platforms=android,ios --org ru.nekoteam --project-name nekowatch .
```

Эта команда добавит папки `android/` и `ios/` и не тронет `lib/`.

### Сборка APK

```bash
./build-apk.sh            # release
./build-apk.sh debug      # отладочный
./build-apk.sh split      # отдельные APK под каждую архитектуру, весят меньше
```

Готовый файл появится в `build/app/outputs/flutter-apk/`.

### ⚠️ Разрешение на интернет

Flutter добавляет разрешение INTERNET **только в отладочный манифест**.
В этом проекте оно вручную прописано в главном:

```xml
<!-- android/app/src/main/AndroidManifest.xml -->
<uses-permission android:name="android.permission.INTERNET"/>
```

Если вы пересоздадите папку `android/`, строку нужно вернуть. Симптом
её отсутствия коварный: в отладке всё работает, а собранный APK молча
показывает пустые экраны, потому что все запросы падают без объяснений.

### Полезные команды

```bash
flutter analyze              # статический анализ, ошибки и предупреждения
dart format .                # форматирование
flutter clean                # снести артефакты сборки, если что-то залипло
flutter run --release        # проверить именно release-поведение
```

## 4. Мини-ликбез по Flutter

Если вы уже пишете на Flutter — пропускайте.

**Всё есть виджет.** Экран, кнопка, отступ, даже выравнивание — это виджеты.
Интерфейс описывается деревом: виджет возвращает другие виджеты из метода
`build()`.

**Два вида виджетов.**

- `StatelessWidget` — не имеет изменяемого состояния, рисует то, что ему
  передали. Пример: `AnimeCarousel`.
- `StatefulWidget` — хранит состояние и умеет перерисовываться по
  `setState()`. Пример: `AnimeDetailsScreen` (хранит загруженные данные).

**Жизненный цикл `StatefulWidget`:**

```
initState()  →  build()  →  ... setState() → build() ...  →  dispose()
   ↑ создали          ↑ рисуем                                  ↑ уничтожили
```

В `initState` запускают загрузку, в `dispose` освобождают контроллеры
и таймеры. Забыть `dispose` — утечка памяти.

**Контроллеры** — объекты, управляющие прокруткой, полем ввода, страницами
и так далее. `ScrollController`, `PageController`, `TextEditingController`.
Их создают как поля класса и обязательно освобождают в `dispose`.

**Sliver-виджеты** — «умные» части прокручиваемой области. `CustomScrollView`
собирает экран из сливеров: `SliverAppBar` (шапка, умеющая схлопываться),
`SliverList`, `SliverGrid`. Нужны, когда шапка должна реагировать на прокрутку.

**`BuildContext`** — позиция виджета в дереве. Через него достают тему
(`Theme.of(context)`), размеры экрана (`MediaQuery.of(context)`) и навигацию.

**Асинхронность.** `Future<T>` — обещание значения в будущем,
`async`/`await` — синтаксис работы с ним. Все сетевые функции возвращают
`Future`.

**`null safety`.** `String` не может быть `null`, `String?` — может.
Оператор `?.` безопасно обращается к возможному `null`,
`??` подставляет значение по умолчанию, `!` утверждает «здесь точно не null»
(и падает, если это неправда — старайтесь его избегать).

## 7. Слой данных: откуда берётся контент

Три внешних источника. Ни один не требует авторизации.

### 7.1 Shikimori — метаданные аниме

Файл: `lib/services/shikimori_api.dart`

Один эндпоинт на всё — списки, поиск, детали, связанные тайтлы:

```
POST https://shikimori.io/api/graphql
User-Agent: NekoWatch (https://github.com/nezdanchick/NekoWatch)
Content-Type: application/json
```

`User-Agent` **обязателен**: без него Shikimori режет запросы. Не убирайте.

**Набор запрашиваемых полей** вынесен в константу и подставляется во все
запросы:

```dart
const String _animesQuery = '''
  id
  name
  russian
  kind
  score
  airedOn { date }
  poster { mainUrl }
''';
```

**Повторные попытки** (`_fetchWithRetry`, максимум 3):

| Ответ сервера | Пауза перед повтором |
|---|---|
| `429` (слишком много запросов) | 2000 мс |
| `5xx` (ошибка сервера) | 1000 мс |
| сеть недоступна | 1000 мс |

**Четыре публичные функции:**

```dart
Future<List<ShikimoriInfo>> fetchAnimeList({
  int page = 1, int limit = 20, String order = 'ranked',
  String? kind, String? status, String? season, int? score,
});

Future<ShikimoriInfo?> fetchAnimeDetails(int id);          // с паузой 300 мс перед запросом
Future<List<ShikimoriInfo>> searchAnime(String query, [int page, int limit]);
Future<List<ShikimoriInfo>> fetchRelatedAnime(int id);
```

**Важная особенность.** Внутренняя функция `_graphqlRequest` перехватывает
любую ошибку и возвращает `null`, а функции выше превращают это в пустой
список. То есть **сбой сети снаружи выглядит так же, как «ничего не найдено»**.
Именно поэтому главная считает полностью пустой результат ошибкой — иначе
пользователь видел бы чёрный экран без единого намёка на причину.

### 7.2 Kodik — озвучки и ссылка на плеер

Файл: `lib/services/kodik_api.dart`

```
GET https://neko-kodik.nezdanchick.deno.net/api/anime/?shikimori_id=<id>&with_material_data=true
```

Это **прокси автора проекта**, развёрнутый на Deno Deploy, а не официальное
API Kodik. Токен не нужен — прокси подставляет свой.

Ссылка на плеер собирается вручную из идентификатора результата:

```dart
withLink['link'] = '$kodikProxyUrl/api/player/?id=${result['id']}';
```

Параметр `with_material_data=true` добавляет в ответ блок `material_data`
с описанием, скриншотами и числом серий — из него берутся текст описания
и галерея на карточке аниме.

Функция бросает исключение при ошибке HTTP или разбора ответа. Экран аниме
оборачивает её в свою обёртку с повторами (10 попыток по 2 секунды).

### 7.3 Collaps — второй плеер

Файл: `lib/services/collaps_api.dart`

```
GET https://neko-collaps.nezdanchick.deno.net/?kinopoisk_id=<id>
```

Если сервер ответил `200`, ссылка считается рабочей и добавляется вторым
пунктом в список плееров.

**Зависимость:** `kinopoisk_id` приходит в ответе Kodik. Значит, если Kodik
не отвечает — Collaps не проверяется вообще. Оба плеера пропадают из-за
одной поломки.

### 7.4 Историческая справка

Раньше прокси жили на доменах `*.deno.dev`; бесплатный деплой истёк,
и оба адреса перестали отвечать. Был промежуточный вариант с прямым
обращением к API Kodik по токену — он удалён как ненужный.

Если прокси снова умрут, прямой доступ выглядит так:

```
POST https://kodik-api.com/search?token=<token>&shikimori_id=<id>&limit=100&with_material_data=true
```

Учтите: прямое API отдаёт ссылки без протокола (`//kodik.info/serial/...`),
их надо дописывать до `https://`, иначе WebView не откроет.

## 8. Модели данных

Папка `lib/models/`. Это простые классы без логики интерфейса.

### 8.1 `ShikimoriInfo` — тайтл

```dart
class ShikimoriInfo {
  final int id;              // идентификатор на Shikimori
  final String name;         // оригинальное название (латиницей)
  final String? russian;     // русское название, может отсутствовать
  final String? posterUrl;   // из poster.mainUrl
  final String? kind;        // tv, movie, ova, ona, special...
  final double score;        // оценка, 0 если нет
  final String? airedOnDate; // дата выхода, формат 'YYYY-MM-DD'
}
```

Рядом лежат правила отображения, тоже перенесённые из оригинала:

```dart
bool canShow(ShikimoriInfo a);        // не музыка и не реклама → показываем
bool canShowSeries(ShikimoriInfo a);  // не фильм и не спешл → есть смысл в числе серий
bool canOpen(ShikimoriInfo a);        // оценка не 0 → тайтл уже вышел, можно открыть
```

`canOpen` — почему тап по некоторым карточкам не открывает экран, а показывает
надпись «Тайтл еще не вышел».

И приоритет сортировки связанных тайтлов:

```dart
const kindPriority = {'tv': 0, 'movie': 1, 'ova': 2, 'ona': 3,
                      'special': 4, 'tv_special': 5, 'web': 6, 'pv': 7};
```

### 8.2 `AnimeStatus` — статус закладки

```dart
enum AnimeStatus { watching, planned, completed, onHold, dropped }
```

У каждого значения два представления:

| Значение | `storageKey` (в базе) | `label` (на экране) |
|---|---|---|
| `watching` | `watching` | Смотрю |
| `planned` | `planned` | В планах |
| `completed` | `completed` | Просмотрено |
| `onHold` | `on_hold` | Отложено |
| `dropped` | `dropped` | Брошено |

Обратите внимание: `onHold` в коде, но `on_hold` в базе — так было в RN,
и менять нельзя, иначе у пользователей слетят закладки.

Константа `allAnimeStatuses` задаёт порядок отображения; и экран закладок,
и лист выбора статуса берут порядок оттуда.


### 8.5 ⚠️ Почему разбор JSON выглядит «слишком осторожным»

Вы заметите, что все `fromJson` принимают `Map<dynamic, dynamic>`, а поля
читаются через проверки вместо прямых приведений типа. Это не перестраховка,
а следствие двух реальных багов.

**Проблема первая — Hive.** Метод `Map<String, dynamic>.from(e)` копирует
только верхний уровень. Вложенный объект (например `poster`) остаётся
`Map<dynamic, dynamic>`, и строка вида

```dart
json['poster'] as Map<String, dynamic>?   // ← падает при чтении из базы
```

бросает ошибку. Внешне это выглядело так: при первом запуске приложение
работало (данные приходили из сети), а после перезахода открывалось белым
экраном и лечилось только очисткой данных приложения.

**Проблема вторая — Kodik.** Сервис отдаёт часть полей то строкой, то числом
(`kinopoisk_id`, `episodes_total`). Жёсткое приведение роняло разбор всего
ответа — и вместо списка плееров пользователь видел «Нет доступных плееров».

Поэтому в `kodik.dart` есть мягкие помощники:

```dart
String? _asString(dynamic value);
int? _asInt(dynamic value);
List<String> _asStringList(dynamic value);
```

**Не заменяйте их на прямые приведения типа.**

## 9. Локальное хранилище

Файл: `lib/services/local_storage.dart`. Обёртка над Hive — быстрой
key-value базой на устройстве.

### Пять хранилищ («боксов»)

| Бокс | Что лежит | Переживает обновление |
|---|---|---|
| `anime_storage` | закладки, история просмотров, версия схемы | да |
| `theme_storage` | выбранная тема | да |
| `time_storage` | суммарные минуты просмотра | да |
| `home_cache` | четыре подборки главной | нет, чистится при миграции |
| `kodik_cache` | карточки аниме, последние 25 | нет, чистится при миграции |

Инициализация происходит в `main()` **до** запуска интерфейса:

```dart
await LocalStorage.init();   // открывает боксы и запускает миграцию
runApp(...);
```

### Кэш карточек аниме

Организован как LRU на 25 записей: при обращении запись перемещается
в конец списка, при переполнении удаляется самая старая (`kodikCacheLimit`).
Хранит и данные Shikimori, и ответ Kodik для конкретного тайтла.

### Версия схемы и миграция

```dart
static const int _cacheSchemaVersion = 3;
```

При запуске сохранённая версия сравнивается с текущей. Если она меньше —
`kodik_cache` и `home_cache` очищаются, а закладки и история остаются.

**Когда поднимать версию:** всякий раз, когда меняется формат кэшируемых
данных или адреса, зашитые внутрь закэшированных записей. Пример из истории
проекта: сменился домен прокси, и в кэше остались ссылки на плеер, ведущие
на мёртвый сервер. Без поднятия версии пользователи так и не увидели бы
рабочих плееров.

### Защита от порчи данных

Чтение кэша обёрнуто в `try/catch`. Если запись не разбирается, она удаляется,
а функция возвращает `null` — приложение просто сходит в сеть вместо того,
чтобы упасть.

## 10. Состояние приложения

Папка `lib/providers/`. Используется Riverpod.

### Как это читать, если не знакомы с Riverpod

Провайдер — глобально доступный контейнер состояния. Виджет подписывается
на него и автоматически перерисовывается при изменении.

```dart
// подписаться и перерисовываться при любом изменении
final state = ref.watch(animeProvider);

// подписаться только на часть состояния — перерисовка реже
final status = ref.watch(animeProvider.select((s) => s.bookmarks[id]));

// прочитать один раз, без подписки (например, внутри обработчика нажатия)
ref.read(animeProvider.notifier).setAnimeStatus(anime, status);
```

Виджет должен быть `ConsumerWidget` или `ConsumerStatefulWidget`, чтобы
получить доступ к `ref`.

Все провайдеры в проекте устроены одинаково: класс состояния (неизменяемый,
с методом `copyWith`) + `StateNotifier`, который его меняет. Восстановление
из базы происходит в конструкторе (`_restore()`), запись — сразу при
изменении.

### 10.1 `animeProvider` — закладки и история

```dart
class AnimeState {
  List<WatchHistoryItem> watchHistory;
  Map<int, AnimeStatus> bookmarks;        // id аниме → статус
  Map<int, ShikimoriInfo> bookmarksData;  // id аниме → сам тайтл
}
```

Две карты, потому что нужно и быстро узнать статус по id, и показать
карточку без похода в сеть.

**Методы:**

```dart
void setAnimeStatus(ShikimoriInfo anime, AnimeStatus? status); // null = убрать
AnimeStatus? getAnimeStatus(int animeId);
List<ShikimoriInfo> getAnimesByStatus(AnimeStatus status);
void addToFavorites(ShikimoriInfo anime);      // это просто статус planned
void removeFromFavorites(int animeId);
bool isFavorite(int animeId);
void addToWatchHistory(int animeId, String title, String image, [String? link]);
void clearWatchHistory();
```

**Правила, унаследованные от оригинала:**

- `addToWatchHistory` удаляет прошлую запись с тем же id, ставит новую
  **в начало** и обрезает список до **100** элементов;
- в списке закладок порядок обратный (новые сверху) — за это отвечает
  `.reversed` на экране закладок.

### 10.2 `homeProvider` — подборки главной

Четыре секции грузятся параллельно, по 25 элементов каждая:

| Секция | Параметры запроса | Заголовок на экране |
|---|---|---|
| popular | `order: 'popularity'` | Популярное аниме |
| latest | `order: 'ranked_shiki'`, `status: 'latest'` | Последние релизы |
| ongoing | `order: 'ranked'`, `status: 'ongoing'` | Онгоинги |
| anons | `order: 'aired_on'`, `status: 'anons'` | Анонсы |

**Логика кэша непривычная:** если запись есть в `home_cache`, сеть
**не опрашивается вообще**. Обновление только вручную — жестом
«потянуть вниз», который сначала чистит кэш. Так было в оригинале.

Состояние содержит флаги `loading`, `refreshing` и `error`. Если после
загрузки все четыре секции пусты, выставляется ошибка «Ошибка при загрузке
данных» с кнопкой «Повторить» — это надстройка Flutter-версии, компенсирующая
то, что клиент Shikimori глушит ошибки (см. раздел 7.1).

### 10.3 `searchProvider` — поиск

- задержка перед запросом (debounce) — **500 мс**;
- минимальная длина запроса — **2 символа** (`minimalQueryLength`);
- размер страницы — **50**;
- подгрузка при достижении половины прокрутки;
- пустой ответ означает «больше нет» (`hasMore = false`).

### 10.4 `themeProvider` — тема

```dart
enum AppThemeMode { light, amoled, monet }
```

Хранит один enum. Значение `dark` из ранних сборок при чтении превращается
в `amoled`, чтобы у старых пользователей ничего не сломалось.

### 10.5 `timeProvider` — счётчик времени

`Timer.periodic` с интервалом в минуту. Запускается в `initState` плеера,
останавливается в `dispose`. Значение сохраняется при каждом увеличении,
чтобы не потерялось при аварийном закрытии.

## 11. Тема и цвета

Файл: `lib/theme/app_theme.dart`.

### Фирменный цвет

```dart
const Color seedColor = Color(0xFF7B68EE);
```

В Material 3 из одного «семенного» цвета генерируется вся палитра:
`primary`, `secondary`, `surface`, `error` и десятки производных.
Функция `ColorScheme.fromSeed` делает это автоматически.

### Три режима

| Режим | Название в интерфейсе | Как строится |
|---|---|---|
| `light` | Светлая | палитра из seed-цвета, светлая |
| `amoled` | Тёмная | тёмная палитра, поверхности выведены в чистый чёрный |
| `monet` | Монет | палитра из обоев системы, светлая/тёмная по настройке телефона |

Режим «Amoled» назван в интерфейсе просто «Тёмная», хотя внутри это
именно amoled-вариант: чёрный `#000000` вместо тёмно-серого. На OLED-экранах
такие пиксели не светятся и экономят батарею.

В `main.dart` выбранный режим раскладывается в пару тем и `themeMode`:

```dart
case AppThemeMode.monet:
  light = buildTheme(lightScheme(lightDynamic));
  dark  = buildTheme(darkScheme(darkDynamic));
  themeMode = ThemeMode.system;      // светлая/тёмная решает система
```

Если устройство не отдаёт динамическую палитру (Android младше 12),
происходит автоматический откат на seed-схемы.

### ⚠️ Почему у карточек есть контуры

У карточек, чипов и сегментированных кнопок явно задана граница:

```dart
side: BorderSide(color: scheme.outlineVariant)
```

Это не украшение. В динамической палитре уровни поверхностей
(`surfaceContainerLow`, `surfaceContainer`, `surfaceContainerHigh`)
отличаются на считанные единицы яркости, и без контура карточки полностью
сливаются с фоном. Убирать нельзя.

### Цвета статусов закладок

Файл: `lib/theme/status_colors.dart`.

Оригинал использовал жёстко заданные цвета: зелёный, синий, фиолетовый,
оранжевый, красный. Брать их напрямую нельзя — в теме «Монет» синяя кнопка
посреди, скажем, терракотового интерфейса выглядит инородно.

Решение: каждый цвет сначала гармонизируется с акцентом текущей темы,
и только потом из него строится схема.

```dart
final statusScheme = ColorScheme.fromSeed(
  seedColor: _seedFor(status).harmonizeWith(scheme.primary),
  brightness: scheme.brightness,
);
```

Функция возвращает три цвета: `container` (фон плашки), `onContainer`
(текст на ней) и `base` (для рамок и акцентов).

### ⚠️ Ловушка контраста в кнопках

```dart
// НЕПРАВИЛЬНО — у titleMedium есть собственный цвет (onSurface),
// он перекроет контрастный onPrimary, и текст станет нечитаемым
label: Text('Смотреть', style: theme.textTheme.titleMedium)

// ПРАВИЛЬНО — размер задаём через стиль кнопки, цвет остаётся её собственным
style: FilledButton.styleFrom(textStyle: theme.textTheme.titleMedium),
label: const Text('Смотреть')
```

Из-за этой ошибки текст на залитой кнопке был почти не виден в теме «Монет».

### Что ещё настроено глобально

`buildTheme` задаёт оформление для `AppBar` (тень только при прокрутке),
`NavigationBar`, `Card` (радиус 16), `ListTile`, `Dialog` (радиус 28),
`BottomSheet` (радиус 28 сверху), `Chip`, `SegmentedButton`,
`FloatingActionButton`, `Divider` и `SnackBar`.

Скругления следуют шкале Material 3: 8 / 12 / 16 / 28.

## 12. Навигация

Файл: `lib/router.dart`. Используется `go_router`.

```
ShellRoute  ← общий каркас с нижней панелью
  /            Главная
  /search      Поиск
  /bookmarks   Закладки
  /profile     Профиль

/anime/:id     Карточка аниме      выезжает справа
/player        Плеер               появляется через затухание, поверх всего
/history       История просмотров
/anime-list    Полный список подборки
```

**Переходы между экранами:**

```dart
context.push('/anime/${anime.id}');                        // с параметром в пути
context.push('/player', extra: {'url': link, 'animeId': id});  // с данными
context.go('/search');                                     // переключить вкладку
```

Разница: `push` кладёт экран поверх (работает кнопка «назад»),
`go` заменяет текущий маршрут.

**`ShellRoute` против `StatefulShellRoute`.** Сейчас используется первый,
поэтому вкладки пересоздаются при каждом переключении — позиция прокрутки
не сохраняется. Если это станет проблемой, менять надо здесь, на
`StatefulShellRoute.indexedStack`.

**Ориентация экрана.** Глобально закреплён портрет в `main()`. Плеер сам
переключается в альбомную и возвращает портрет при выходе.

## 13. Экраны

### 13.1 `shell_screen.dart` — каркас

Держит нижнюю панель `NavigationBar` с четырьмя пунктами и подставляет
в тело текущий экран вкладки.

Важно: массив путей `_tabPaths` и список `destinations` должны совпадать
по порядку — активная вкладка определяется поиском текущего пути в массиве.

### 13.2 `home_screen.dart` — главная

**Что видно:** заголовок «NekoWatch», четыре горизонтальные подборки,
у каждой кнопка «Все» справа.

**Что происходит:**

- при первом построении `homeProvider` сам начинает загрузку;
- пока пусто и идёт загрузка — крутится индикатор;
- при неудаче — карточка с текстом ошибки и кнопкой «Повторить»;
- жест «потянуть вниз» чистит кэш и грузит заново;
- если история не пуста, внизу поверх содержимого висит баннер
  «продолжить просмотр» — он прячется при прокрутке и возвращается
  при остановке, а свайпом в сторону убирается **визуально**
  (из истории запись при этом не удаляется — так было в оригинале).

### 13.3 `search_screen.dart` — поиск

Поле `SearchBar` в шапке с автофокусом при открытии вкладки, ниже сетка
результатов. Подгрузка следующей страницы происходит при достижении
половины прокрутки.

Тексты пустых состояний: `^///^` до ввода, «Введите не менее 2 символов»
при коротком запросе, «Ничего не найдено» при пустом ответе,
«Ошибка при поиске» при сбое.

### 13.4 `bookmarks_screen.dart` — закладки

Самая нетривиальная вёрстка из вкладок:

```
NestedScrollView
├── шапка: SliverAppBar «Закладки»
└── тело: Column
    ├── ряд чипов (горизонтальный ListView)
    └── PageView из шести сеток   ← Все + пять статусов
```

Три способа переключения работают согласованно:

1. свайп по содержимому листает `PageView`;
2. при смене страницы ряд чипов подкручивается так, чтобы активный чип
   оказался по центру (`Scrollable.ensureVisible` с `alignment: 0.5`);
3. тап по чипу плавно листает страницу (`animateToPage`, 300 мс).

Каждая страница помнит свою позицию прокрутки благодаря `PageStorageKey`.

### 13.5 `profile_screen.dart` — профиль

Три секции: активность (время просмотра, переход в историю с числом записей),
оформление (переключатель тем), о нас (карточки разработчиков, Telegram,
GitHub). Внизу версия приложения из `package_info_plus`.

Ссылки открываются во внешнем браузере через `url_launcher`.

### 13.6 `anime_details_screen.dart` — карточка аниме

Самый сложный файл проекта. Разберём по частям.

**Порядок загрузки:**

1. Читается кэш — если есть, экран сразу рисуется с ним.
2. Параллельно идут два запроса: детали с Shikimori и озвучки с Kodik.
   Каждый обёрнут в `_fetchWithRetry` — до 10 попыток с паузой 2 секунды.
3. Отдельно, не блокируя экран, грузится блок «Связанное».
4. Результаты пишутся в кэш.

**Скриншоты.** Берутся из `material_data.screenshots`. Каждый URL
нормализуется — Shikimori отдаёт их с поддоменов CDN, которые не всегда
доступны:

```dart
url.replaceAll(RegExp(r'https?://(nyaa|dere)\.shikimori\.(one|io)'),
               'https://shikimori.io')
```

**Бесконечная галерея.** Реализована так: `PageView.builder` **без**
`itemCount`, индекс берётся по модулю длины списка. Чтобы работал свайп
и назад тоже, при загрузке вызывается `_centerScreenshotLoop()` —
он прыгает на страницу `length * 1000`, то есть в середину бесконечной ленты.

> Если вы добавляете новое место, где присваиваются `_screenshots`,
> не забудьте вызвать `_centerScreenshotLoop()` после `setState`.

**Шапка.** `SliverAppBar` высотой 360 с параллаксом. Пока она развёрнута,
название не дублируется в панели (оно и так крупно написано ниже), а кнопка
«назад» имеет тёмную подложку поверх картинки. При схлопывании подложка
плавно исчезает, иконка перекрашивается под фон, а в панели проявляется
название. За переключение отвечает слушатель прокрутки и флаг
`_headerCollapsed`.

**Ниже шапки:** название (тап разворачивает длинное), оригинальное название,
ряд чипов (оценка, тип, год), блок кнопок и плееров, описание, «Связанное».

### 13.7 `player_screen.dart` — плеер

Открывает ссылку плеера в `WebView`. Логика перенесена из оригинала буквально:

- до **5** попыток перезагрузки с паузой **3000 мс** при ошибке;
- пока грузится — чёрный экран с индикатором;
- после исчерпания попыток — «Не удалось загрузить видео»;
- если ссылка пуста — «Видео недоступно»;
- фон всегда чёрный, тема не применяется;
- системные панели скрыты, экран переводится в альбомную ориентацию;
- вставляется скрипт, блокирующий `touchmove` (иначе страница плеера
  «резинит» под пальцем);
- здесь же запускается и останавливается счётчик времени просмотра.

> **Не заменяйте `WebView` на нативный видеоплеер.** Плееры сторонние,
> это встроенные страницы, а не прямые ссылки на видеофайлы.

### 13.8 `anime_list_screen.dart` и `history_screen.dart`

Первый — постраничный список для одной подборки (получает `title` и `type`
через `extra`), с догрузкой при прокрутке.

Второй — список истории с кнопкой «Очистить историю» и подтверждением
через `AlertDialog`.

## 14. Переиспользуемые виджеты

### 14.1 `anime_card.dart` — карточка аниме

Ключевой виджет, встречается на всех экранах со списками.

**Принцип: карточка не задаёт себе размер.** Она растягивается под ячейку
сетки или под `SizedBox` в карусели. Постер занимает всё свободное место
(`Expanded`), подпись снизу имеет фиксированную высоту 36 пикселей ровно
под две строки.

Раньше размер был жёстким (160×260), из-за чего длинные названия обрезались
на полуслове, а сетка выглядела рвано. Текущая схема эту проблему снимает.

**Константы раскладки экспортируются отсюда** — все сетки и карусели
ссылаются на них, так что менять размеры нужно только в одном месте:

```dart
const double kAnimeCardWidth = 164;        // ширина в горизонтальной карусели
const double kAnimeCarouselHeight = 300;   // высота карусели
const double kAnimeGridMaxExtent = 190;    // максимальная ширина ячейки сетки
const double kAnimeGridAspectRatio = 0.56; // пропорции ячейки
```

Сетки используют `SliverGridDelegateWithMaxCrossAxisExtent`, а не фиксированное
число колонок. На телефоне получается 2 колонки, на планшете само станет 3–4
без единой правки.

**Взаимодействие:**

| Действие | Результат |
|---|---|
| Тап | открыть карточку аниме |
| Тап, если оценка = 0 | на 1.2 секунды показать `¯\_(ツ)_/¯` «Тайтл еще не вышел» |
| Долгое нажатие | открыть лист выбора статуса + виброотклик |

Отдельной кнопки «в избранное» на карточке нет — она загромождала постер.
Если тайтл уже в закладках, в углу постера появляется кружок с иконкой
закладки в цвете статуса (он не перехватывает нажатия).

Поверх постера сверху — плашка с типом, годом и оценкой.

### 14.2 `anime_carousel.dart`

Заголовок секции, кнопка «Все» справа и горизонтальный список карточек.
Если данных нет, виджет не рисует ничего.

### 14.3 `anime/anime_actions.dart` — кнопки и плееры

Два блока.

**Ряд кнопок.** Обе одной высоты (56) и формы (радиус 18), но разного веса —
чтобы не сливались в кашу:

- «Смотреть» — `FilledButton`, залитая акцентом, главное действие;
- «В закладки» / название статуса — `OutlinedButton`, рамка и иконка
  в цвете статуса.

**Список плееров.** Заголовок и список живут в одной карточке: тап по
заголовку раскрывает список внутри неё же (`AnimatedSize`, 250 мс,
шеврон поворачивается). Это выглядит цельно, в отличие от прежнего варианта,
где список висел отдельным блоком.

Три различимых состояния, которые раньше выглядели одинаково:

| Состояние | Что показывается |
|---|---|
| Идёт загрузка | «Ищем плееры…» + индикатор |
| Запрос упал | «Не удалось загрузить плееры» на красном фоне + кнопка повтора |
| Плееров правда нет | «Нет доступных плееров» |

### 14.4 `anime/status_selector.dart` — выбор статуса

Экспортирует функцию, а не виджет:

```dart
Future<void> showAnimeStatusSheet(BuildContext context, WidgetRef ref, ShikimoriInfo anime);
```

Её вызывают и карточка (долгим нажатием), и экран аниме (кнопкой).

У листа обязательно `useSafeArea: true`, `isScrollControlled: true`
и нижний отступ по `viewPadding` — иначе последние пункты уезжают
под полоску жестов Android.

### 14.5 `history/watch_history_tile.dart`

Плитка истории: постер, название, дата, кнопка воспроизведения.

Флаг `floating` включает тень и более плотную поверхность — он нужен для
баннера на главной, который висит поверх содержимого и без этого сливался
со списком.

### 14.6 `history/continue_watching_banner.dart`

Оборачивает плитку в `Dismissible`, чтобы её можно было смахнуть.
Смахивание скрывает баннер **визуально**, из истории запись не удаляется.

### 14.7 `theme_selector.dart` и `time_spent_card.dart`

Первый — `SegmentedButton` с тремя темами и иконками.
Второй — плитка «Время просмотра» с пересчётом минут в часы и минуты.

### 14.8 `anime/anime_meta_row.dart`

Ряд характеристик тайтла. **Написан, но нигде не подключён** — ровно как
в оригинале, где соответствующий компонент импортировался, но не отрисовывался.
Оставлен как рабочая заготовка.

## 15. Сквозные сценарии

Полезно проследить, как данные проходят через слои.

### Запуск приложения

```
main()
  ├── WidgetsFlutterBinding.ensureInitialized()
  ├── LocalStorage.init()            открывает 5 боксов Hive
  │     └── _migrateCaches()         чистит кэши, если схема устарела
  ├── SystemChrome.setPreferredOrientations([portraitUp])
  └── runApp(ProviderScope(NekoWatchApp))
        └── DynamicColorBuilder      спрашивает у системы палитру обоев
              └── MaterialApp.router
                    ├── тема из themeProvider
                    └── appRouter → ShellScreen → HomeScreen
```

При построении `HomeScreen` создаётся `homeProvider`, его конструктор
вызывает `loadData()` — четыре параллельных запроса или чтение кэша.

### Тап по карточке аниме

```
AnimeCard._handleTap()
  └── canOpen(anime)?
        ├── нет  → показать оверлей «Тайтл еще не вышел» на 1.2 с
        └── да   → context.push('/anime/42')
                     └── AnimeDetailsScreen.initState → _load()
                           ├── _loadFromCache()     мгновенно рисуем, что есть
                           └── _loadFromNetwork()
                                 ├── fetchAnimeDetails(42)         Shikimori
                                 ├── searchKodikByShikimoriId(42)  Kodik
                                 ├── fetchRelatedAnime(42)         фоном
                                 └── LocalStorage.setKodikCacheEntry(...)
```

### Нажатие «Смотреть»

```
AnimeActions._handlePlay()
  └── _handleWatchPress(link)
        ├── animeProvider.addToWatchHistory(id, title, poster, link)
        │     └── запись в Hive, обрезка списка до 100
        └── context.push('/player', extra: {url: link, animeId: id})
              └── PlayerScreen.initState
                    ├── timeProvider.startTracking()   таймер на минуту
                    ├── альбомная ориентация, скрытие системных панелей
                    └── WebViewController.loadRequest(url)
```

При выходе `dispose()` останавливает таймер и возвращает портрет.

### Добавление в закладки долгим нажатием

```
AnimeCard._handleLongPress()
  ├── HapticFeedback.mediumImpact()
  └── showAnimeStatusSheet(context, ref, anime)
        └── выбор статуса
              └── animeProvider.setAnimeStatus(anime, status)
                    ├── обновление двух карт в состоянии
                    ├── запись в Hive
                    └── перерисовка всех подписанных виджетов
                          (кружок на карточке, экран закладок, кнопка на карточке аниме)
```

## 16. Как внести типовое изменение

### Добавить новое поле из Shikimori

1. Дописать поле в `_animesQuery` в `shikimori_api.dart`.
2. Добавить поле в `ShikimoriInfo`, разобрать его в `fromJson`
   через мягкие проверки, добавить в `toJson`.
3. Поднять `_cacheSchemaVersion` в `local_storage.dart` — иначе у части
   пользователей останется кэш без нового поля.
4. Использовать поле в интерфейсе.

### Добавить третий плеер

1. Создать сервис в `services/` по образцу `collaps_api.dart`.
2. Дописать пункт в `_availablePlayers` в `anime_actions.dart` — это
   единственное место, где собирается список плееров.

### Добавить статус закладки

1. Новое значение в `AnimeStatus` (`storageKey` — строка, `label` — надпись).
2. Цвет в `_seedFor` в `status_colors.dart`.
3. Добавить в `allAnimeStatuses` — экран закладок и лист выбора подхватят
   его автоматически.

### Поменять размер карточек

Только константы в начале `anime_card.dart`. Все сетки и карусели
ссылаются на них.

### Добавить экран

1. Файл в `screens/`.
2. Маршрут в `router.dart`.
3. Если это вкладка — добавить путь в `_tabPaths` и пункт в `destinations`
   в `shell_screen.dart`, **в том же порядке**.

### Поменять цветовую гамму

`seedColor` в `app_theme.dart`. Вся палитра пересчитается автоматически.
Цвета статусов подстроятся сами за счёт гармонизации.

## 17. Отладка и типичные проблемы

### Как смотреть логи

```bash
flutter run              # логи идут в консоль
flutter logs             # если приложение уже запущено
```

В коде расставлены `print` в ключевых местах — все с пометкой
`// ignore: avoid_print`. Ищите строки:

| Строка в логе | О чём говорит |
|---|---|
| `GraphQL request error:` | сбой запроса к Shikimori |
| `Request error Kodik API:` | сбой запроса к Kodik |
| `Kodik proxy: HTTP ...` | прокси ответил, но с ошибкой |
| `Кэш главной повреждён` | битая запись в базе, она удалена |
| `Кэш аниме повреждён` | то же для кэша карточек |

### Каталог уже случавшихся проблем

Все они исправлены, но полезно знать симптомы — если что-то похожее
всплывёт снова, вы сразу поймёте, куда смотреть.

| Симптом | Причина | Где смотреть |
|---|---|---|
| Пустая главная только в собранном APK | нет разрешения INTERNET в главном манифесте | `android/app/src/main/AndroidManifest.xml` |
| Белый экран при повторном запуске, лечится очисткой данных | поверхностный `Map.from` + жёсткое приведение вложенного объекта | `models/anime.dart`, `models/kodik.dart` |
| «Нет доступных плееров» | умер прокси; либо приведение типа у поля, которое пришло числом вместо строки | `services/kodik_api.dart`, `models/kodik.dart` |
| Нечитаемый текст на кнопке в теме «Монет» | `textTheme` передан в `label`, перекрыл контрастный цвет | `widgets/anime/anime_actions.dart` |
| Названия обрезаются, сетка рваная | карточка с жёстким размером внутри ячейки другого размера | `widgets/anime_card.dart` |
| Синяя кнопка в фиолетовом интерфейсе | цвет статуса без гармонизации с темой | `theme/status_colors.dart` |
| Нижние пункты листа под полоской жестов | нет `useSafeArea` у `showModalBottomSheet` | `widgets/anime/status_selector.dart` |
| Всё сливается в один цвет в теме «Монет» | у карточек убрали контур | `theme/app_theme.dart` |

### Чек-лист перед коммитом

```bash
flutter analyze     # ноль ошибок
dart format .       # единое форматирование
flutter run         # проверить руками основные сценарии
```

Проверить стоит: главная грузится, поиск находит, карточка открывается,
плеер запускается, закладка ставится долгим нажатием, все три темы
переключаются, приложение переживает перезапуск.

### Чего лучше не делать

| Не делать | Почему |
|---|---|
| Менять адреса, тела запросов, паузы повторов, размеры страниц | нарушает соответствие оригиналу |
| Возвращать `as Map<String, dynamic>` в разборе JSON | роняет приложение при чтении из базы |
| Менять формат кэша без поднятия версии схемы | у пользователей остаются битые записи |
| Заменять `WebView` нативным плеером | плееры — сторонние страницы |
| Убирать INTERNET из главного манифеста | release-сборка теряет сеть |
| Передавать цветной стиль текста в `label` кнопки | ломает контраст |
| Убирать контуры карточек | интерфейс сливается в тёмных и динамических темах |
| Переписывать русские тексты | они перенесены из оригинала дословно |
| Менять что-либо за пределами `nekowatch_flutter/` | там живёт исходное RN-приложение |

## 18. Глоссарий

**Sliver** — часть прокручиваемой области, умеющая реагировать на прокрутку.
Из сливеров собирается `CustomScrollView`.

**Провайдер (Riverpod)** — глобально доступный контейнер состояния,
на который подписываются виджеты.

**Бокс (Hive)** — именованное хранилище ключ-значение на устройстве.

**Seed-цвет** — исходный цвет, из которого Material 3 генерирует всю палитру.

**Material You / Monet** — механизм Android 12+, отдающий приложениям
палитру, построенную по обоям пользователя.

**Гармонизация цвета** — сдвиг оттенка в сторону акцента темы, чтобы
посторонний цвет не выбивался из общей гаммы.

**Debounce** — задержка перед выполнением действия, чтобы не реагировать
на каждое нажатие клавиши. В поиске — 500 мс.

**LRU-кэш** — кэш, из которого при переполнении удаляется запись,
к которой дольше всего не обращались.

**Онгоинг** — аниме, которое выходит прямо сейчас, серия за серией.

**Тайтл** — одно произведение (сериал, фильм, OVA) целиком.

**Озвучка** — вариант перевода от конкретной студии. Kodik отдаёт по одной
записи на озвучку.
